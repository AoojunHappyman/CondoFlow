### (Unit and Tenant Management System - Interactive High-Fidelity Web Application Prototype)

**CondoFlow** คือเว็บแอปพลิเคชันต้นแบบเสมือนจริง (Interactive High-Fidelity Web Application Prototype) ที่ออกแบบและพัฒนาขึ้นตามหลักวิศวกรรมซอฟต์แวร์, UX/UI ระดับองค์กร, และกระบวนการวิเคราะห์ระบบ (Business Analysis) เพื่อเป็นศูนย์กลางการบริหารจัดการคอนโดมิเนียมอย่างครบวงจร ลดขั้นตอนเอกสาร ลดความซ้ำซ้อนของข้อมูล และเชื่อมต่อการทำงานระหว่าง **ผู้ดูแลระบบ (Admin)**, **เจ้าของห้อง (Owner)**, **ผู้เช่า (Tenant)** และ **ผู้ใช้งานทั่วไป (General User)**

> 💡 **จุดเด่นของ Prototype:**
> - สามารถคลิกโต้ตอบได้จริงทุกเมนู ฟอร์ม ตาราง คิวตรวจสอบ และ Modal **ไม่มีปุ่มหลอก ไม่มีข้อความ "Coming Soon"**
> - จัดเก็บข้อมูลจำลองลงใน **Local Storage** ถาวร ข้อมูลไม่สูญหายเมื่อรีเฟรชหน้าเว็บ พร้อมปุ่ม Reset Demo Data
> - จำลอง **Network Latency 300–700 ms** พร้อมแสดงผลด้วย **Skeleton Loading** เหมือนระบบจริง
> - รองรับ **Responsive Design** 100% (Desktop, Tablet, และ Mobile พร้อม Bottom Navigation)
> - รองรับ **Dark Mode / Light Mode** สลับได้ทันทีทุกหน้า
> - มาตรฐานภาษาไทยทางการกำกับภาษาอังกฤษ วันที่แบบ พ.ศ. (เช่น 5 พฤศจิกายน 2569) และสกุลเงินบาท (`฿8,500.00`)

## 1. ข้อมูลบัญชีสำหรับทดลองใช้งาน (Demo Accounts)

ระบบมาพร้อมกับ **Demo Mode Switcher Bar** บริเวณด้านบนสุดของหน้าจอ เพื่อให้ผู้ตรวจประเมินสามารถคลิกสลับบทบาทไปมาระหว่าง 4 บทบาทได้ใน 1 วินาที หรือจะเข้าสู่ระบบผ่านหน้า Login ก็ได้:

| บทบาท (Role) | Username | Password | สิทธิ์และขอบเขตข้อมูลตัวอย่าง |
| :--- | :--- | :--- | :--- |
| **ผู้ดูแลระบบ (Admin)** | `admin` | `Admin@123` | เข้าถึงได้ทุกฟังก์ชัน ทุกหน้าจอ 25 FR และ Audit Log |
| **ผู้เช่า (Tenant)** | `tenant` | `Tenant@123` | ผู้เช่าห้อง **A-1205** (นายสมบัติ มีทรัพย์) ดูสัญญา ชำระเงิน แจ้งซ่อม รับพัสดุ |

*หมายเหตุ: ในหน้า Login มีปุ่ม **"เข้าสู่ระบบด้วยบัญชีทดลอง" (Quick Demo Login)** เพื่อเข้าใช้งานบทบาทใดๆ ได้ทันทีโดยไม่ต้องพิมพ์*

## 2. สถาปัตยกรรมเทคโนโลยี (Tech Stack)

- **Frontend Core**: React 19, TypeScript 5.9, Vite 8.3
- **CSS Styling & Design System**: Tailwind CSS v3.4, Custom Design Tokens, CSS Variables
- **Icons**: Lucide React
- **Data Visualization**: Recharts (Bar Charts, Line/Area Charts, Pie Charts)
- **Delight & Animations**: Canvas Confetti (แสดงเมื่อชำระเงินสำเร็จ / อนุมัติสลิป)
- **Data Persistence**: Local Storage API (คีย์ `condoflow_v1_*`)
- **Navigation**: Hash-based Router (`#dashboard`, `#admin/units`, `#units/unit-a-1205`) รองรับ Deep-linking และเปิดบน Static Hosting/GitHub Pages ได้ทันทีโดยไม่ต้องพึ่ง Server Config
- **Typography**: รองรับภาษาไทยสมบูรณ์ด้วย Google Fonts `Prompt` (หัวข้อ) และ `IBM Plex Sans Thai` (เนื้อหา)

## 3. ขั้นตอนการติดตั้งและเริ่มใช้งาน (Getting Started)

### ความต้องการของระบบ (Prerequisites)
- [Node.js](https://nodejs.org/) เวอร์ชัน 18 ขึ้นไป (แนะนำ 20 LTS หรือ 22+)
- ตัวจัดการแพ็กเกจ `npm`

### วิธีการรันบนเครื่อง Local

1. เปิด Terminal หรือ PowerShell แล้วเข้าไปที่โฟลเดอร์ของโปรเจกต์:
   ```bash
   cd C:\Users\ASUS\.gemini\antigravity\scratch\condoflow
   ```

2. ติดตั้ง Dependencies (หากยังไม่ได้ติดตั้ง):
   ```bash
   npm install --legacy-peer-deps
   ```

3. รัน Development Server:
   ```bash
   npm run dev
   ```

4. เปิดเบราว์เซอร์แล้วเข้าใช้งานที่ URL:
   ```text
   http://localhost:5173
   ```

5. ทดสอบการ Build สำหรับ Production:
   ```bash
   npm run build
   ```

## 4. ผังกระบวนการทำงานหลัก 7 ส่วนตาม DFD

### DFD 1: จัดการบัญชีผู้ใช้และสิทธิ์ผู้ใช้งาน (Account & RBAC Management)
- **สมัครสมาชิก (Register)**: มีเครื่องมือวัดความแข็งแกร่งของรหัสผ่านแบบ Real-time (Checklist: ความยาว 8+ ตัว, พิมพ์ใหญ่, ตัวเลข, อักขระพิเศษ) บังคับกดยอมรับนโยบายความเป็นส่วนตัว
- **เข้าสู่ระบบ (Authentication)**: รองรับ Remember Me, ตรวจจับ Password ไม่ถูกต้อง, บันทึกการเข้าสู่ระบบลงใน Audit Log
- **Session Timeout Simulator**: ระบบจำลองการแจ้งเตือนเซสชันหมดอายุจากการไม่ขยับหน้าจอ 30 นาที พร้อมหน้าต่างนับถอยหลัง 60 วินาที ให้ผู้ใช้เลือก "ต่ออายุเซสชัน" หรือ "ออกจากระบบ"
- **ตารางควบคุมสิทธิ์ (Role & Permission Matrix)**: หน้า `/admin/roles` ผู้ดูแลระบบสามารถคลิกเปลี่ยนสิทธิ์ อ่าน/เขียน/ลบ/อนุมัติ ในแต่ละโมดูลได้แบบ Real-time พร้อม Dialog ยืนยันการเปลี่ยนแปลง
- **แก้ไขข้อมูลส่วนตัว (Profile)**: หน้า `/profile` เปลี่ยนรหัสผ่าน อัปเดตเบอร์โทรศัพท์ และจำลองการอัปโหลดรูปประจำตัว

### DFD 2: จัดการข้อมูลห้องชุด เจ้าของห้อง ผู้เช่า และสัญญาเช่า (Units, Owners, Tenants & Leases)
- **จัดการห้องชุด (Units Page)**:
  - รองรับทั้งมุมมอง **การ์ด (Grid Cards)** และ **ตาราง (Table View)**
  - ตัวกรองละเอียด: กรองตามอาคาร (อาคาร A, อาคาร B), ชั้น, สถานะห้อง (ว่าง, มีผู้เช่า, ติดจอง, บำรุงรักษา), และช่วงราคา
  - เพิ่ม / แก้ไขห้องชุด พร้อม Validation ขนาดพื้นที่, จำนวนห้องนอน/ห้องน้ำ, ราคาเช่า, ค่าส่วนกลาง
  - **Business Rule Check**: หากห้องชุดยังมีสัญญาเช่าที่ยังไม่หมดอายุ (Active Lease) ระบบจะ **ปฏิเสธการลบห้องชุดทันที** พร้อมแสดง Alert แจ้งเตือน
  - นำออกข้อมูลเป็นไฟล์ Excel/CSV ด้วยการรองรับภาษาไทย (UTF-8 BOM) และจำลองการนำเข้าไฟล์ CSV
  - หน้ารายละเอียดห้องชุด (Unit Detail): แกลเลอรีรูปภาพ, ข้อมูลจำเพาะ, สัญญาเช่าปัจจุบัน, บิลค้างชำระ และประวัติการแจ้งซ่อมของห้องนั้นๆ
- **จัดการเจ้าของห้องและผู้เช่า (Owners & Tenants)**:
  - แยกแท็บ: เจ้าของห้อง (Owners), ผู้เช่า (Tenants), และบัญชีทั้งหมด (Users)
  - เพิ่มเจ้าของห้องพร้อมผูกความสัมพันธ์กับห้องชุด
  - วงจรชีวิตผู้เช่า (Tenant Lifecycle Transition): เปลี่ยนสถานะผู้เช่า (กำลังเช่า -> สัญญาใกล้หมดอายุ -> ย้ายออกแล้ว -> ยกเลิกสัญญา/Blacklist) พร้อมแบบฟอร์มระบุเหตุผลและคำอธิบายผลกระทบ (Impact Note)
- **จัดการสัญญาเช่า (Lease Contracts)**:
  - เพิ่มสัญญาเช่าใหม่: เลือกระยะเวลา (6 เดือน, 1 ปี, 2 ปี) คำนวณเงินประกันการเช่า (Deposit) 2 เดือนอัตโนมัติ
  - ดูเอกสารสัญญาเช่าฉบับเต็ม พร้อมฟังก์ชัน **"พิมพ์สัญญาเช่า" (Printable Lease Agreement PDF View)**
  - ขอยกเลิกสัญญาเช่าก่อนกำหนด พร้อมฟิลด์ระบุเหตุผลและวันที่สิ้นสุดผลบังคับใช้

### DFD 3: จัดการค่าใช้จ่าย ใบแจ้งหนี้ และการชำระเงิน (Billing, Invoices & Payments)
- **การสร้างใบแจ้งหนี้ (Invoice Creation)**:
  - ออกใบแจ้งหนี้รายห้อง (Single Invoice) ระบุหมวดหมู่: ค่าส่วนกลาง, ค่าน้ำประปา, ค่าไฟฟ้า, ค่าที่จอดรถ, ค่าปรับ, ค่าบริการอื่นๆ พร้อมคำนวณภาษีมูลค่าเพิ่ม VAT 7%
  - **สร้างใบแจ้งหนี้แบบกลุ่ม (Batch Invoicing)**: สร้างค่าส่วนกลางประจำงวดพร้อมกันทั้งอาคาร A หรือ B ได้ในคลิกเดียว
  - ใบแจ้งหนี้จำลองรองรับการพิมพ์/ออกเป็น PDF ฉบับทางการ
- **การแจ้งชำระเงินโดยผู้เช่า (Tenant Payment Submission)**:
  - ผู้เช่าเปิดดูใบแจ้งหนี้ที่ค้างชำระ กดปุ่ม "แจ้งชำระเงิน"
  - เลือกวิธีชำระ: สแกน PromptPay QR Code, โอนเงินผ่านธนาคาร, หรือบัตรเครดิต
  - แนบภาพสลิปหลักฐานการโอนเงิน (จำลองการอัปโหลดหรือเลือกสลิปตัวอย่าง) กรอกวัน-เวลาและเลขอ้างอิง
  - เมื่อส่งข้อมูลแล้ว สถานะของบิลจะเปลี่ยนเป็น **"รอตรวจสอบสลิป" (Pending Verification)** ทันที
- **คิวตรวจสอบการชำระเงิน (Admin Payment Verification Queue)**:
  - หน้าจอ `/admin/payments` แสดงรายการรอตรวจสอบสลิปทั้งหมด
  - คลิกดูรูปสลิปขนาดใหญ่ (Zoomable Slip Preview) เปรียบเทียบยอดเงิน วันที่ และเลขบัญชี
  - **กด "อนุมัติการชำระเงิน"**: อัปเดตสถานะบิลเป็น `Paid` โดยอัตโนมัติ ส่งการแจ้งเตือนไปยังผู้เช่า บันทึก Audit Log และยิงเอฟเฟกต์ Confetti
  - **กด "ปฏิเสธการชำระเงิน"**: มี Dialog บังคับระบุเหตุผลในการปฏิเสธ (เช่น สลิปไม่ชัด, ยอดเงินไม่ตรง) เพื่อแจ้งเตือนกลับไปยังผู้เช่าให้ส่งหลักฐานใหม่

### DFD 4: จัดการคำร้องแจ้งซ่อม (Maintenance & Repair Ticketing)
- **การเปิดคำร้องแจ้งซ่อม (Tenant Request Submission)**:
  - ผู้เช่าเลือกห้องชุด หมวดหมู่งานซ่อม (ประปา, ไฟฟ้า, เครื่องปรับอากาศ, โครงสร้าง, เฟอร์นิเจอร์, ส่วนกลาง)
  - กำหนดระดับความเร่งด่วน: ต่ำ, ปกติ, สูง, หรือฉุกเฉิน (Emergency 24 ชม.)
  - แนบรูปถ่ายจุดที่ชำรุด ระบุช่วงเวลาที่สะดวกให้ช่างเข้าตรวจ
- **หน้าจอจัดการงานซ่อม (Repairs Kanban & Table)**:
  - รองรับทั้งมุมมอง **Kanban Board** 4 คอลัมน์ (รอดำเนินการ -> มอบหมายช่างแล้ว -> อยู่ระหว่างซ่อม -> ดำเนินการเสร็จสิ้น) และมุมมอง **ตาราง (Table View)**
  - ผู้ดูแลระบบสามารถลากการ์ดหรือคลิกปุ่มเพื่อส่งต่องาน มอบหมายช่างผู้รับผิดชอบ และนัดหมายวันเข้าบริการ
  - ขั้นตอนปิดงาน: ช่างกรอกบันทึกการซ่อม (Completion Notes), แนบรูปถ่ายหลังซ่อมเสร็จ, และระบุค่าใช้จ่าย (หากมี)
  - **ประเมินความพึงพอใจ (Satisfaction Rating)**: ผู้เช่าสามารถให้คะแนนดาว 1-5 ดาว พร้อมข้อติชมหลังจากงานเสร็จสิ้น

### DFD 5: จัดการข้อมูลพัสดุ (Parcel Delivery & QR Code Handover)
- **การลงทะเบียนรับพัสดุเข้าโครงการ (Admin Inbound Log)**:
  - เจ้าหน้าที่บันทึกบริษัทขนส่ง (Kerry, Flash, ไปรษณีย์ไทย, J&T, Shopee Express ฯลฯ)
  - เลขพัสดุ (Tracking No.), ชื่อผู้รับ, ห้องชุด, และตำแหน่งจัดเก็บบนตู้/ชั้นวาง (เช่น Shelf A-03)
  - ระบบจะสุ่มสร้าง **รหัสรับพัสดุ 6 หลัก (Pickup Code)** และ **QR Code ประจำพัสดุ** โดยอัตโนมัติ
  - ส่งการแจ้งเตือนไปยังแอปพลิเคชันของผู้เช่าห้องนั้นทันที
- **การรับพัสดุของผู้เช่า (Tenant Pickup View)**:
  - ผู้เช่าจะเห็นรายการพัสดุที่ยังไม่ได้รับ พร้อมรหัส PIN และ QR Code สำหรับแสดงต่อเจ้าหน้าที่
- **การส่งมอบพัสดุ (Handover Verification)**:
  - เจ้าหน้าที่เปิดหน้าจอส่งมอบพัสดุ กรอกรหัส PIN 6 หลักเพื่อยืนยันตัวตน
  - เมื่อรหัสถูกต้อง ระบบจะเปลี่ยนสถานะเป็น **"รับพัสดุแล้ว" (Picked Up)** บันทึกเวลาที่รับจริง และชื่อเจ้าหน้าที่ผู้ส่งมอบ

### DFD 6: จัดการประกาศและการแจ้งเตือน (Announcements & Notification Center)
- **จัดการประกาศโครงการ (Announcements Module)**:
  - ผู้ดูแลระบบสร้างประกาศข่าวสาร: หัวข้อ, หมวดหมู่, กำหนดกลุ่มเป้าหมาย (ทุกคน, ลูกบ้านอาคาร A, ลูกบ้านอาคาร B, เฉพาะผู้เช่า, เฉพาะเจ้าของห้อง)
  - ฟังก์ชัน **"ปักหมุดประกาศสำคัญ" (Pin to Top)** สำหรับเรื่องเร่งด่วน เช่น การล้างถังพักน้ำ, การซ้อมหนีไฟ
  - กล่องแสดงตัวอย่างประกาศ (Rich Preview Box)
- **ศูนย์การแจ้งเตือน (Notification Center)**:
  - กระดิ่งแจ้งเตือนบน Navbar พร้อมตัวเลขนับจำนวนรายการที่ยังไม่อ่าน (Unread Badge)
  - หน้าต่าง Popover สรุป 5 รายการล่าสุด และหน้าต่างใหญ่ `/notifications`
  - รองรับการกรอง: ทั้งหมด, เฉพาะที่ยังไม่อ่าน, และอ่านแล้ว
  - ปุ่ม **"ทำเครื่องหมายว่าอ่านแล้วทั้งหมด" (Mark All as Read)**
  - คลิกที่การแจ้งเตือนเพื่อเปิดไปยังรายการที่เกี่ยวข้องได้ทันที (Deep Link ไปยังบิล, งานซ่อม, หรือพัสดุ)

### DFD 7: จัดการรายงานสรุปและบันทึกกิจกรรม (Analytics, Reports & Audit Log)
- **ระบบรายงานและสถิติ (Reports & Analytics)**:
  - หน้า `/admin/reports` มีแท็บรายงาน 5 มิติ:
    1. **ภาพรวมโครงการ (Executive KPI)**: อัตราการเข้าพัก (Occupancy Rate), สรุปห้องชุดทั้งหมด
    2. **สถานะห้องชุด (Unit Breakdown)**: กราฟสัดส่วนห้องว่าง vs มีผู้เช่า vs ซ่อมบำรุง
    3. **การเงินและรายได้ (Financial Revenue)**: กราฟแท่งเปรียบเทียบยอดเรียกเก็บ vs ยอดจัดเก็บจริง vs ยอดค้างชำระ ย้อนหลัง 6 เดือน
    4. **การซ่อมบำรุง (Maintenance Turnaround)**: กราฟงานซ่อมแยกตามหมวดหมู่และระยะเวลาเฉลี่ยในการปิดงาน
    5. **การรับพัสดุ (Parcel Pickup Performance)**: ระยะเวลาเฉลี่ยที่ลูกบ้านมารับพัสดุ
- **ประวัติการทำรายการ (Transaction History)**:
  - บันทึกการเงินและกิจกรรมของผู้ใช้งานแต่ละคนแบบแยกอิสระ (User-isolated Ledger)
  - สามารถค้นหา กรองตามช่วงวันที่ และส่งออกเป็นไฟล์ CSV
- **บันทึกกิจกรรมระบบ (System Audit Log)**:
  - บันทึกแบบ **Read-only ไม่สามารถแก้ไขหรือลบได้**
  - บันทึก Timestamp (Asia/Bangkok), ชื่อผู้กระทำ, บทบาท, การกระทำ (Action), โมดูล, รายละเอียด (Before/After), และ IP Address

## 6. เมทริกซ์สิทธิ์การเข้าถึง (Role & Permission Matrix - RBAC)

ระบบออกแบบตามหลักการ **Least Privilege**:

| โมดูล / ฟังก์ชันการทำงาน | ผู้ดูแลระบบ (Admin) | เจ้าของห้อง (Owner) | ผู้เช่า (Tenant) | ผู้ใช้ทั่วไป (User) |
| :--- | :---: | :---: | :---: | :---: |
| **ดูภาพรวมแดชบอร์ดระบบ** | ✅ เต็มรูปแบบ | ❌ | ❌ | ❌ |
| **ดูข้อมูลห้องชุด** | ✅ ทั้งหมด (20 ห้อง) | ✅ เฉพาะห้องตนเอง (A-1205, B-0808) | ✅ เฉพาะห้องที่เช่า (A-1205) | ✅ เฉพาะห้องที่เปิดเช่า |
| **เพิ่ม / แก้ไข / ลบห้องชุด** | ✅ ทำได้ทุกห้อง | ❌ อ่านอย่างเดียว | ❌ อ่านอย่างเดียว | ❌ |
| **ส่งออก / นำเข้าไฟล์ CSV ห้องชุด** | ✅ ทำได้ | ❌ | ❌ | ❌ |
| **จัดการเจ้าของห้องและผู้เช่า** | ✅ ทำได้ทุกบัญชี | ❌ ดูผู้เช่าห้องตนเองได้ | ❌ ดูตนเองเท่านั้น | ❌ |
| **จัดการสัญญาเช่า (สร้าง/ยกเลิก)** | ✅ ทำได้ทุกสัญญา | ✅ ดูสัญญาห้องตนเอง | ✅ ดูสัญญาตนเอง | ❌ (แสดง 403) |
| **ออกใบแจ้งหนี้ (เดี่ยว/กลุ่ม)** | ✅ ทำได้ทุกหมวด | ❌ | ❌ | ❌ (แสดง 403) |
| **ตรวจสอบและอนุมัติสลิปโอนเงิน** | ✅ ทำได้ทุกสลิป | ❌ | ❌ | ❌ (แสดง 403) |
| **แจ้งชำระเงินและแนบสลิป** | ✅ ทำแทนลูกบ้านได้ | ✅ จ่ายค่าส่วนกลาง | ✅ จ่ายค่าเช่า/น้ำ/ไฟ | ❌ (แสดง 403) |
| **แจ้งซ่อมห้องชุด** | ✅ แจ้งได้ทุกจุด | ✅ แจ้งห้องตนเอง | ✅ แจ้งห้องตนเอง/ส่วนกลาง | ✅ แจ้งสอบถามทั่วไป |
| **มอบหมายช่างและปิดงานซ่อม** | ✅ ดำเนินการได้ | ❌ ติดตามสถานะ | ❌ ประเมินคะแนนดาว | ❌ |
| **รับพัสดุเข้า / ส่งมอบพัสดุ** | ✅ ดำเนินการได้ | ❌ | ❌ รับด้วย QR/PIN | ❌ (แสดง 403) |
| **สร้างประกาศโครงการ** | ✅ สร้างและปักหมุด | ❌ อ่านอย่างเดียว | ❌ อ่านอย่างเดียว | ✅ อ่านประกาศทั่วไป |
| **ดูรายงานสรุปและสถิติ (Recharts)** | ✅ 5 แท็บรายงาน | ❌ | ❌ | ❌ (แสดง 403) |
| **แก้ไขตารางสิทธิ์บทบาท (RBAC)** | ✅ ปรับปรุงได้ | ❌ | ❌ | ❌ (แสดง 403) |
| **ดูประวัติกิจกรรม (Audit Log)** | ✅ ทั้งหมด | ❌ | ❌ | ❌ (แสดง 403) |

## 8. ข้อกำหนดด้านคุณภาพและความมั่นคงปลอดภัย (Non-Functional Requirements)

1. **เป้าหมายความพร้อมใช้งาน 99% SLA (Maintenance Mode Simulation)**:
   - ผู้ดูแลระบบสามารถกดเปิด **โหมดปิดปรับปรุงระบบ (Maintenance Mode)** ได้จากหน้า Settings หรือ Navbar
   - เมื่อเปิดโหมดนี้ ผู้ใช้งานทั่วไป เจ้าของห้อง และผู้เช่าที่เข้าสู่ระบบจะพบหน้าจอ **503 Service Unavailable** แจ้งช่วงเวลาที่ระบบจะเปิดให้บริการตามมาตรฐานสากล
   - ผู้ดูแลระบบสามารถคลิกปุ่มเพื่อปิดโหมดบำรุงรักษาและกลับสู่การทำงานปกติได้ตลอดเวลา
2. **การรักษาความปลอดภัยของข้อมูลส่วนบุคคล (PDPA & Data Masking)**:
   - หมายเลขบัตรประจำตัวประชาชน 13 หลักถูกแสดงผลด้วยเทคนิค Data Masking เสมอ เช่น `1-1002-XXXXX-XX-1`
   - หมายเลขโทรศัพท์ถูกซ่อน 4 ตัวกลาง เช่น `081-XXX-4567`
3. **ระบบตรวจสอบและป้องกันเซสชันค้าง (30-Minute Idle Session Timeout)**:
   - จำลองระบบตรวจจับการไม่มีกิจกรรม หากไม่มีการคลิกหรือพิมพ์หน้าจอ ระบบจะแสดง Modal เตือนพร้อมนับถอยหลัง 60 วินาที ให้ผู้ใช้ต่ออายุหรือบังคับ Logout เพื่อป้องกันคนอื่นมาใช้งานหน้าจอค้างไว้
4. **ความสมบูรณ์และถูกต้องของข้อมูล (Audit Log Immutability)**:
   - ทุกการเปลี่ยนแปลงสำคัญ (การอนุมัติสลิป, การเปลี่ยนสิทธิ์, การลบห้อง, การปิดงานซ่อม) จะถูกส่งเข้าสู่บันทึกกิจกรรม Audit Log ทันทีพร้อม Timestamp ในประเทศไทย
5. **การตอบสนองที่รวดเร็วและเป็นมิตร (Zero Broken Elements)**:
   - ไม่มีลิงก์ตาย (No 404 dead link ภายในกระบวนการปกติ)
   - มี Skeleton Loading จำลองเวลาดาวน์โหลด 300–700 ms เพื่อสร้างประสบการณ์เสมือนระบบระดับองค์กรที่แท้จริง
